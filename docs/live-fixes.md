# Исправления по скриншотам — 25 октября 2026 года

## Место для погоды

Прежний фильтр предпочитал точное написание перед полным названием с продолжением.
Для «Ростов» это оставляло украинский населённый пункт и отбрасывало
Ростов-на-Дону и Ростов Великий. Теперь сохраняются точное имя и продолжения
по границе слова/дефиса; «Ростовка» не становится «Ростовом». При нескольких
местах бот уточняет вариант. Указанный пользователем `Ростов-на-Дону` ищется
как полное название; страна без указания пользователя не угадывается.

Москва и Казань проверены на захваченных публичных ответах Open-Meteo;
повторяющиеся подписи не дают `INVALID_ARGUMENTS`. Если это сообщение остаётся
в уже запущенном экземпляре, нужно перезапустить процесс/пересобрать образ:
его код не обновляется сам при изменении исходников. Маленькие населённые
пункты не отсеиваются по населению. Санкт-Петербург в Монтсеррате есть в
источнике; без страны бот должен уточнить, а не молча подменить место.
Подробности и реальные фикстуры — [погодный поиск](weather.md).

## Напоминание на английском

Локальная проверка раньше знала только русские глаголы и относительные даты.
Модель могла распознать `Remind me tomorrow at 11:00 to submit the report`,
но проверка отвергала её корректный результат. Добавлены английские просьбы,
`today`/`tomorrow`, интервалы и AM/PM. Неизвестные даты/часы по-прежнему требуют
уточнения; время модели сверяется с пользовательским текстом и сохранённой
IANA-зоной. Подготовка карточки не означает запись: требуется кнопка владельца.
Ни промпт, ни число вызовов для исправления не менялись.

## `/why` и неуспешный аудит

При тайм-ауте финальной транзакции прежняя реализация не оставляла следа нового
запроса, и `/why` показывал предыдущее решение. Теперь начало запроса сохраняется
до сети отдельной короткой транзакцией, без удержания соединения во время LLM.
Финальные событие и состояние запроса по-прежнему сохраняются атомарно.
При новом запросе без итогового события `/why` явно сообщает, что последнее
решение ещё не сохранено, и не выдаёт прежнюю Москву за объяснение Петербурга.

Конечный тайм-аут записи увеличен с двух до пяти секунд; повторов LLM/MCP нет.
Устойчивость проверяется и при перекрывающихся запросах: сравнивается начало
связанного запроса, а не поздняя отметка commit старого ответа. Точную причину
исходной задержки БД по одному скриншоту установить нельзя.

## Проверки

Telegram и LLM в регрессиях подменены. Погодный поиск дополнительно проверен
публичными HTTP-запросами без OpenRouter. PostgreSQL-регрессия реально отменяет
медленный финальный аудит и проверяет rollback, перезапуск, `/reset`, изоляцию
владельца и завершение того же запроса без нового LLM.

Первый полный прогон не засчитан: после завершения сессии среды остановился
фоновый Docker, 26 интеграционных проверок не смогли подготовить БД. Его отчёт
сохранён в [lab2-screenshots-initial-checks.json](evaluation/lab2-screenshots-initial-checks.json).
После запуска Docker в постоянной сессии прошёл новый полный прогон:
[lab2-screenshots-checks.json](evaluation/lab2-screenshots-checks.json).
Успешны 1312 тестов без пропусков и все 28 критериев ЛР2; зависимости,
Ruff и форматирование проверены. Реальная LLM-квота на эти регрессии не расходовалась.
Исходные миграции и теги `lab1`/`lab2` не перемещаются.
