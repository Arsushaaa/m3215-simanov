# Дополнительная свободная проверка смысла формулировок

Пользователь попросил продолжить атаки после выпуска lab3: проверять необычные
фразы и переписку, где случайное слово может стать городом/расписанием/записью.
Следующий ввод выбирается по фактическому ответу, гипотеза и текст сохраняются
до API. Это не заранее подобранный набор успешных ответов.

Новая сессия на исходниках локального lab3, отдельная PostgreSQL и синтетические
пользователи. Настоящие обработчики/LLM/MCP, отправка Telegram подменена.
Исходный тег lab3 не перемещается. Дополнительные ключи _2/_3 разрешены ранее;
основной ключ не используется. Предел каждого слота равен оставшейся квоте,
прочитанной до регистрации, а не новым50 после каждой сессии. Все отказы и
ошибки остаются в журнале. При изменении app — новый протокол и повтор проверки.

Фокус: переносные значения «напомни»/«пары»/«погода», цитаты и чужие слова,
отрицания, границы времени, смена намерения между репликами, проверяемая запись
и правдивость утверждений об отмене. Обнаружение проблемы оценивается по ответу,
фактическим вызовам и состоянию БД, а не по одному названию маршрута.

## Найденные ошибки

8ходов,14LLM (_2),cost0. Учебное «напомни», вопрос о погоде в чужой цитате,
метафорические «погода/пары» и название столбца «погода в Казани» не вызвалиMCP.

Ход5 после настоящего callback: модель обещала отмену подтверждённого reminder,
хотя запись осталась в БД иMCP не вызывался. Ход7 при просьбе переноса существующей
записи назвал её несохранённой и попросил уточнить уже известную дату. Обе ошибки
сохранены с фактическим состоянием. У приложения нет операции удаления/переноса
подтверждённых напоминаний; исправление сообщает эту границу и не добавляет запись.

Исправление: Schedule не показывает свободную прозу как результат действия,если
операции/наблюдения нет. При пустой pending отмена не объявляется успешной.
Уточнения Schedule выбираются моделью из конечных вопросов об отсутствующих
параметрах; произвольная фраза в question отвергается. Это не разбор пользовательских
слов регулярками: смысл выбирает LLM,право и результат ограничивает приложение.
Карточка нового напоминания явно сообщает,что прежние сохранённые не изменятся.
Положительные карточки,чтение расписания и отмена pending проверяются отдельно.
