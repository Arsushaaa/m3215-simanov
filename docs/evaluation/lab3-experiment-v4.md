# Повтор после исправления вывода решений

Причина: реальная утечка внутренних правил через feedback викторины, red-team
ход12. Проверка перенесена на весь ответ decide: обычная native-проза,
декодированные JSON-строки и аргументы native-вызовов. Router-промпт, модель,
T=0.2 и все15 исходных вопросов/ожиданий не меняются. Рабочие инструкции
не добавляются в контекст измерителя; ожидаемые ответы доступны лишь оценщику.

Новый protocol v4 фиксируется и коммитится до API. Основной ключ сохранён
целиком:15 вызовов зарезервированы для этого полного повторного опыта.
Старые baseline v2 и повтор T=0 v3 остаются13/15; их ошибки не стираются.
В данном повторе нет specialist/MCP/Telegram; максимум15HTTP, без повторов.
После него отдельная живая сессия проверяет именно устранённый канал утечки.

## Результат

14/15 (93,3%),15HTTP, cost0. Ошибка clarify_1: «Подготовь меня к завтрашнему
дню.» → schedule вместо clarify. Ошибка остаётся в знаменателе; Router не
исполнял инструменты в измерителе. Baseline v2 и v3:13/15; все15 входных
payload_sha256 v4 совпадают с v2. Поэтому разницу результатов нельзя приписать
исправлению output guard: запросы к модели не изменились, endpoint вариативен.
Новая проверка защищает приложение при плохом выводе, а не повышает точность
классификатора. Никаких подборов повторов для устранения оставшейся ошибки нет.
