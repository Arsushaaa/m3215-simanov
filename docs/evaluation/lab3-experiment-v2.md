# Действующий протокол ЛР3 v2, до реальных вызовов

Протокол: [lab3-experiment-v2-protocol.json](lab3-experiment-v2-protocol.json).
Условия модели и неизменные 15 запросов те же, что в [первой предрегистрации](lab3-experiment.md):
NVIDIA free, T0.2, native, 6000/2048, часы12.10.2026 09:00 Europe/Moscow,
15 попыток без повторов; ожидаемые цели не поступают модели.

Причина новой версии — до первой реальной генерации исправлено ожидание двух
захваченных сводок: теперь они готовятся параллельно, в пределах lease. Это
не изменение Router-промпта или вопросов. Дополнительно исправлен инвариант
интеграционного теста: max_size1 с успешным SQL внутри внешнего callback вместо
требования полностью простаивающего пула при параллельных источниках.

Старый протокол8e3041c и checkpoint с insufficient_quota сохранены без переписывания.
В них **0 реальных LLM-попыток**, поэтому они не оценивают качество модели.
Новая версия хранит новые SHA кода/измерителя; старый source не выдаётся за текущий.
CLI по умолчанию теперь использует v2. Перед run этот JSON коммитится.

```bash
.venv/bin/python -m scripts.lab3_experiment run
```

Результат — `lab3-experiment-v2-results.json`, включая каждый неуспех и latency/usage.
Если квоты меньше всех оставшихся случаев, генераций не будет. Восстановление
CLI не повторяет начатые попытки. Следующее исправление после реального baseline
потребует отдельной предрегистрации с сохранением всей истории.

Счётчик `free_model_daily_requests` относится к текущим суткам UTC, по
[документации OpenRouter](https://openrouter.ai/docs/api/reference/limits).
Для Europe/Moscow границаUTC соответствует03:00. Новый ключ сам по себе не
увеличивает общий лимит. После границы CLI всё равно проверяет реальный остаток.
