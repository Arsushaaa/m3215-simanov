# ЛР2: реальный эксперимент маршрутизации

19 октября 2026 года выполнены три полных прогона неизменных
[12 запросов](lab2-routing.json). Исходные результаты сохранены:
[начальный](lab2-results-initial.json), [первая редакция правил](lab2-results-policy-v1.json),
[итоговый](lab2-results.json). Все результаты используются в анализе; ошибки не удалялись.

## Методика до измерения

Модель `nvidia/nemotron-3-super-120b-a12b:free`, режим `structured`,
`temperature=0.3`, `max_tokens=2048`, LLM timeout 60 с, agent timeout 135 с,
контекст 6000 по оценке приложения, история до 20 сообщений, `reasoning.enabled=false`.
Предел цены prompt/completion равен нулю. Во всех трёх прогонах эти настройки
одинаковы; API вернул тот же model ID. Проверка [публичного каталога](lab2-provider-evidence.json)
подтверждает нулевую цену и структурированный вывод; платного fallback нет.

Часы приложения фиксированы: `2026-10-12T09:00:00+03:00`, зона `Europe/Moscow`.
Каждый кейс получает пустую историю и отдельное хранилище в памяти.
Используются настоящие `DialogService`, `AgentService` и OpenRouter HTTP-клиент.
Каталог схем получается настоящим MCP stdio discovery. Чтение останавливается
перед прикладным MCP-вызовом; напоминание проходит обычную проверку proposal
и времени. PostgreSQL, Telegram, погода, подтверждение и финальная генерация
не вызываются. Это эксперимент выбора действия и аргументов; сквозное выполнение
инструментов отдельно подтверждено приёмкой и независимым MCP-клиентом.

Запрос модели содержит пользовательский вопрос, обычный промпт и обнаруженные
схемы. Ожидаемые действия, аргументы и ID кейсов в него не включаются.
Скрипт хранит исходный видимый JSON решения, API model/ID, finish reason,
токены/стоимость, временные отметки, hash запроса, кода и каталога. Скрытое
reasoning и произвольные поля API не сохраняются.

Метрика действия требует точного совпадения. Ключи аргументов совпадают точно;
для текста нормализуются регистр, пробелы, «ё/е» и конечные `.?!`, для даты требуется
точная дата, для времени — тот же aware UTC-момент. Смысловые алиасы и добавленная
от себя страна не засчитываются. Проверка будущего времени и совпадения с
пользовательским запросом остаётся штатной. Пропущенный нужный вызов даёт ошибку;
знаменатели всегда 12 и 9, включая подмножества и сбои.

`clarify_1` не содержит точного времени и обрабатывается локальным reminder guard:
в каждом полном прогоне **11 реальных LLM-вызовов, один локальный ответ**.
Это оценка всего пути приложения, а не двенадцать независимых решений модели.
В строках чтения `status=captured_before_mcp`: измерительный перехват останавливает
вызов исключением. Поэтому соответствующий audit может иметь `status=FAILED`
и один достигнутый MCP-вызов; фактических прикладных MCP-операций в эксперименте ноль.

## Анализ ошибок и одно изменяемое решение

Исходный прогон: `weather_3` вернул обычный ответ с выдуманной температурой
и утверждением о якобы выполненном инструменте; вызова не было. `schedule_1–3`
выбрали недельный ресурс вместо требуемого дневного инструмента. Такой ресурс
мог содержать нужную дату, но не соответствует ожидаемому действию набора.
`respond_1` также ошибочно выбрал ресурс для объяснения Python.

Изменён один элемент решения — блок правил выбора действия в первом промпте
`app/agent.py`. В v1 явно разделены обычный ответ, текущая погода, один день,
неделя целиком и подготовка напоминания. Схемы, модель, температура, часы,
пользовательские запросы и валидаторы не менялись. Повторён весь набор,
включая каждый исходный ошибочный случай.

В v1 исправлены `weather_3`, `schedule_1–2` и `respond_1`. В `schedule_3`
осталась ошибка: теперь модель попросила дату воскресенья. Кроме того,
`weather_2` добавил «Россия» к «Казань», а `reminder_3` попросил
базовое время для «через два часа», несмотря на известные часы приложения.
В той же части промпта (v2) уточнены сохранение указанного места без дополнений
и вычисление относительных дат/интервалов из доверенных часов.
Вновь повторены все 12 кейсов, включая три ошибочных. Итог: **12/12 и 9/9**,
пороги 10/12 и 8/9 выполнены.

Протоколы различаются только hash `app/agent.py` в разделе исходников;
остальные параметры, источник схем и код измерителя совпадают. Комментарии
о причинах ошибок являются анализом наблюдаемых решений, а не скрытыми
рассуждениями модели. Полные три прогона потребовали **33 реальных API-вызова**,
суммарная API-стоимость в сохранённом usage — **0**. Автоматических повторов,
выбора удачных ответов внутри прогона и смены модели нет.

## Воспроизведение

Из корня, с настроенным локальным `.env` и Python 3.12:

```bash
source scripts/env.sh
python -m scripts.lab2_experiment --env-file .env --output .deploy/evaluation/lab2-repeat.json
```

Новый путь создаёт новый эксперимент и расходует до 12 бесплатных запросов.
Существующий checkpoint с тем же протоколом возобновляет только ещё не начатые
кейсы; занятый прерванный запрос фиксируется как ошибка и не повторяется.
Несовпадение hash набора/кода/настроек запрещает продолжение прежнего файла.
Для явного повтора отдельных ошибок используйте новый файл и `--case ID`:

```bash
python -m scripts.lab2_experiment --env-file .env --output .deploy/evaluation/lab2-selected.json --case schedule_3
```

Подмножество не считается полной приёмкой и не уменьшает знаменатели.
`--max-api-calls 0` запрещает генерацию; это проверка ограничений измерителя,
которая не подтверждает качество модели. Unit-тесты измерителя выполняются
командой `python -m pytest -q tests/test_lab2_experiment.py` без реального API.

Малый открытый набор использован для уточнения правил, поэтому итог не является
оценкой на независимой скрытой выборке. Одного успешного прогона недостаточно
для гарантии будущего поведения. OpenRouter model ID — alias внешнего endpoint,
а не локально закреплённые веса; повторная генерация может отличаться.
