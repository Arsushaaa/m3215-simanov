# Повтор после ошибки ложной отмены

Причина — реальная дополнительная атакующая сессия,ход5: модель заявила,что
подтверждённое напоминание отменено,но оно осталось в БД. Исправление ограничивает
свободный вывод Schedule,вводит проверенные вопросы уточнения,сверяет наличие
pending перед сообщением об отмене и обозначает,что новая карточка не редактирует
подтверждённые записи. SQL/лимитыLLM/MCP/Router-промпт не меняются.

Протоколv6 фиксируется доAPI. Все15 исходных запросов/ожиданий,модель,T=0.2,
часы,схемаRouter и пустая история неизменны. Порог12/15. Все ошибки сохраняются.
Явно выбран OPENROUTER_API_KEY_3 — без fallback. Основной ключ сохраняет20
запросов,включая обязательный резерв15. На_3 до запуска43; максимум15HTTP.

```bash
.venv/bin/python -m scripts.lab3_experiment run --key-env OPENROUTER_API_KEY_3
```

Исходный локальныйlab3 не перемещается. Результат новой версии не приписывается
исходному тегу; если приёмка пройдена,создаётся новыйlab3-final-v2.

## Результат

12/15(80%),15HTTP,cost0. Все12 доменных запросов маршрутизированы правильно,
все3 ожидаемых clarify ошибочны: clarify_1→schedule,clarify_2/3→legacy_study.
Они остаются ошибками в исходном знаменателе15. Порог12/15 пройден ровно.
Все15 payload_sha256 совпадают сbaselinev2,v4,v5; изменение результата не
приписывается фиксу,потому что Router не получает новые инструкции Schedule.
Никакого повтора ради лучшего числа не будет. Основной ключ не использован.
