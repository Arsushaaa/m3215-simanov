# ЛР2: сравнение двух бесплатных моделей с неизменным промптом

## Методика, зафиксированная до запросов — 25 октября 2026 года

Прежние три прогона 7/12 → 10/12 → 12/12 сохранены в
[историческом отчёте](lab2-experiment.md). В них действительно выполнялись
реальные API-вызовы, но между прогонами менялся промпт на основании ошибок
того же набора. Это разработка промпта, а не независимая сравнительная оценка.
Запросы и критерии набора не переписывались. Старые результаты не заменяются.

Новый эксперимент сравнивает **Xing4.0 29B A4B (free)** и
**dots-3-note-preview (free)**. Обе модели на момент подготовки представлены
в [публичном каталоге OpenRouter](https://openrouter.ai/api/v1/models) с нулевой
ценой входа/выхода и поддержкой `temperature`, `max_tokens`, `reasoning` и
строгого JSON по схеме. Снимок каталога и endpoint сохраняется рядом с манифестом.
Модель работающего бота и `.env` этим сравнением не меняются.

### Что меняется и что фиксируется

Фактор модели имеет два значения; у каждой модели измеряется обычная для бота
температура **0,3** и заранее выбранная альтернатива **0**. Гипотеза: снижение
случайности может уменьшить ошибки выбора действия и точных аргументов.
Это гипотеза до измерения, не обещание улучшения; температура 0 не гарантирует
детерминизм у внешнего провайдера.

Промпт, схемы, код валидации, неизменные [12 запросов](lab2-routing.json),
пустая история каждого случая и доверенные часы/зона фиксируются до вызовов.
Часы — `2026-10-12T09:00:00+03:00`, зона — `Europe/Moscow`. Лимит вывода 2048,
контекст 6000, до 20 сообщений истории, LLM timeout 60 секунд, agent timeout 135,
`reasoning.enabled=false`, режим `structured`. `top_p`, seed и penalties
одинаково не передаются; остаются defaults провайдеров. Модельные defaults
поэтому являются ограничением сравнения, а не ещё одним измеренным фактором.

Лимит вывода специально не меняется: приложение упоминает его в промпте,
и такое изменение нарушило бы условие неизменного текста. Никаких правок
промпта по результатам нового эксперимента не будет.

До первого вызова коммитится `lab2-comparison/manifest.json` с SHA-256 исходников,
набора, полным планом и дополнительными случаями. Измеритель отказывается
запускаться с незакоммиченным манифестом или изменённым кодом. Для каждого кейса
сверяется hash сообщений и схем без `model`/`temperature` между четырьмя
конфигурациями. Ожидаемые ответы и ID случаев не передаются модели.

### Порядок и оценки

Выполняется один полный прогон каждой из четырёх конфигураций. Внутри каждого
кейса конфигурации чередуются; начальная позиция циклически сдвигается.
Это уменьшает влияние времени запуска, хотя не устраняет дрейф внешнего API.
Каждая попытка сначала сохраняется в checkpoint, затем отправляется.
Ошибки API, неверный JSON, отказ схемы и обрыв входят в общий знаменатель,
не повторяются автоматически и не заменяются удачным ответом.

Метрики и нормализация совпадают с исходным измерителем: **действия ≥10/12,
аргументы ≥8/9**. Страна, добавленная к месту без указания пользователя,
не считается точным аргументом. Даты сравниваются точно, время — по UTC-моменту,
текст — с прежней нормализацией регистра, пробелов и конечной пунктуации.
Во всех клетках один случай без точного времени уточняется локально:
на 12 запросов приходится **11 реальных LLM-вызовов**, всего 44 в сетке.
Это оценка пути приложения; локальный случай не приписывается модели.

Правило выбора фиксируется до измерения: сначала конфигурации, прошедшие оба
порога, затем больше правильных аргументов, затем действий, затем меньшая
температура, затем model ID по алфавиту. Выбирается одна целая конфигурация,
а не удачные ответы из разных прогонов. Если ни одна не прошла пороги,
результат эксперимента — неуспех, даже если выбрана лучшая из имеющихся.

### Дополнительная проверка и сквозной сценарий

Четыре новые формулировки и их точная оценка включены в манифест **до сетки**:
погода в Лиссабоне, расписание послезавтра, английское напоминание на завтра
в 11:00 и объяснение `break`. Они выполняются только у выбранной конфигурации,
не используются для её выбора и не исправляются после просмотра ответов.
Это дополнительная проверка новых формулировок; автор уже видел ошибки бота,
поэтому она не объявляется слепой независимой выборкой. Для неё отдельно
показываются 4/4 действий и 3/3 аргументов, без смешивания с основными 12/9.

Затем тот же вариант выполняет один настоящий сквозной сценарий:
«Покажи расписание на 13 октября 2026 года». Действительно вызываются
OpenRouter → MCP stdio → учебное расписание → OpenRouter с запрещёнными
инструментами. Сохраняются результат, видимые ответы и счётчики, максимум
два LLM и один MCP. Telegram не вызывается; SQL заменён отдельным хранилищем
в памяти; напоминания не создаются. Это не проверка доставки в Telegram.

Общий бюджет — **44 + 4 + 2 = 50** бесплатных запросов. Все HTTP-вызовы
ограничены нулевой ценой; платного запасного endpoint нет. Дополнительные
повторы для получения красивого результата не предусмотрены.

### Границы выводов

Главный набор уже использовался при разработке промпта: новый эксперимент
измеряет влияние модели/температуры на известном наборе, а не обобщение на
произвольные вопросы. Один ответ на случай не оценивает статистическую
стабильность. Надёжность транзакций, подтверждений, изоляции и ошибок доставки
проверяется отдельными тестами PostgreSQL/MCP; она не выводится из процента
правильных решений модели.

## Воспроизведение

```bash
source scripts/env.sh
python -m scripts.lab2_comparison --prepare --folder docs/evaluation/lab2-comparison
# Сохранить код и манифест отдельным коммитом перед запуском.
python -m scripts.lab2_comparison --run --folder docs/evaluation/lab2-comparison
```

Новая папка означает новый расход квоты. Готовые checkpoints не повторяют
начатые попытки; исходные отчёты и манифест нельзя перезаписывать. Обновление
промпта/кода требует нового протокола, который нельзя объединять с этим.

### Как получен выбор

1. При обычной температуре 0,3 сравнили модели с одинаковыми входами.
   dots прошла пороги; Xing — нет. У Xing в каждой клетке восемь отказов 429,
   они остались в знаменателях. Успешные ответы обслуживали AtlasCloud для dots
   и Phala для Xing. Доступность endpoint не доказывает превосходство языковых
   способностей модели; точный уровень ограничения 429 в ответах не сохранён.
2. Проверили заранее выбранное снижение температуры до 0. У dots результат
   ухудшился: `schedule_3` запросил уточнение вместо расписания ближайшего
   воскресенья. Видимый ответ также ошибочно называет воскресеньем 12 октября
   2026 года — по фиксированным часам это понедельник. Промпт не переписывался.
3. У dots при обеих T в `reminder_2` правильны дата/часы, но текст равен
   «Проверить расписание на 15 октября» вместо «проверить расписание».
   Строгая метрика аргументов считает это ошибкой. Выбранный результат —
   **8/9, а не 9/9**; порог выполнен без округления или смыслового пересчёта.
   У Xing T=0 в `weather_2` добавлены не указанные пользователем уточнения:
   «Казань, Татарстан, Россия» вместо «Казань» — аргументы также ошибочны.
4. Только целая конфигурация **dots, T=0,3** прошла оба порога. Она выбрана
   по предварительному правилу; удачные строки разных прогонов не смешивались.
5. После выбора [четыре новые формулировки](lab2-comparison/extra.json)
   дали **4/4 действий и 3/3 аргументов**. Английская просьба со скриншота
   сформировала точное предложение напоминания на завтра, 11:00 в сохранённой
   зоне. Запись без подтверждения не выполнялась.
6. [Сквозное чтение](lab2-comparison/live-read.json) прошло: два OpenRouter-вызова,
   один настоящий MCP `get_schedule`, дата 13 октября, `local_schedule`,
   финальный HTTP с `tools=[]`, ответ сохранён в изолированной памяти.
   Ручная сверка подтвердила обе пары, интервалы 10:40–12:10 / 12:40–14:10
   и аудитории 103/104 из MCP. В тексте осталась опечатка «аудитария».

Итог выполняет заявленные пороги и дополнительные проверки. Снижение T
не улучшило результат в этом прогоне. Один прогон не доказывает оптимальную
температуру вообще или стабильное превосходство модели.

### Расход и проверка

Ровно **50 попыток: 44 в сетке, 4 дополнительных, 2 сквозных**. У 34 ответов
сохранены API ID и `usage.cost=0`; у 16 отказов сведения о стоимости не переданы.
Заявленная цена и `provider.max_price` равны нулю. Дополнительных генераций
для получения лучшего результата не делалось.

`GET /key` сразу после опыта показал 32 учтённых бесплатных запроса и остаток
18 из 50. Это отдельный счётчик на момент чтения: отказы могут учитываться
иначе, данные — обновляться с задержкой. Он не заменяет журнал наших 50 попыток.

Общие проверки: [1312 тестов без пропусков и 28 критериев](lab2-screenshots-checks.json).
Неудачный первый прогон из-за остановившегося Docker сохранён отдельно и описан
в [исправлениях](../live-fixes.md). Модель в `.env` сравнением не менялась.
