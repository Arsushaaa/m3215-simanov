# Как работает тренировка `/quiz`

После `/quiz` бот ждёт понятную тему по программированию. Например:

```text
/quiz
мое имя
→ уточнение темы, счётчик остаётся 0
python
→ Вопрос 1/5
ответ на первый вопрос
→ обратная связь, затем Вопрос 2/5
```

Уточнение, отказ и подсказка не считаются новым вопросом. Тема закрепляется
после первого принятого вопроса. Для смены темы начните новую тренировку `/quiz`.
После ответа на пятый вопрос бот показывает итог; просьба о подсказке или
уточнение на пятом шаге оставляют тренировку активной.

Состояние хранится в прежних полях PostgreSQL: тема, номер вопроса, завершение.
Изменение прогресса и пара сообщений записываются одной транзакцией с проверкой
ревизии. Повтор update возвращает сохранённый ответ; сброс во время генерации
отклоняет устаревший результат. Новых миграций и настроек для исправления нет.

## Один запрос к модели

`DialogService` запрашивает строгий `QuizTurn` через существующий LLM-клиент:
`kind` (`question`, `clarify`, `hint`, `finished`), `feedback` и `text`.
Код в `app/quiz.py` проверяет разрешённый переход, отделяет обратную связь
от следующего вопроса и сам добавляет один номер. Модель не передаёт счётчик.
Лишние ведущие заголовки удаляются; второй номерной заголовок в теле отклоняется.
Числа и заголовки внутри блоков кода сохраняются. Незакрытый блок кода в
обратной связи закрывается перед собственным заголовком приложения.

Уточнение не закрепляет отвергнутую тему. Только полный `question` увеличивает
номер; `finished` разрешён после пятого вопроса. Подсказка оставляет текущий шаг.
JSON-схема учитывается в бюджете контекста; MCP и дополнительные LLM-запросы
для проверки темы или перегенерации не используются.

Если JSON целиком прочитан, но API пометил результат как неполный, бот показывает
доступный текст с предупреждением, не продвигая номер/завершение. По «Продолжи»
восстанавливается тип незавершённого ответа из сохранённого программного заголовка,
в том числе после пересоздания сервиса. Продолжение подсказки не становится новым
вопросом. Сырой незакрытый JSON не является пользовательским ответом: при ошибке
формата бот просит повторить сообщение, не записывает его и сохраняет прогресс.

Проверки используют подменённую модель и настоящую PostgreSQL отдельно:

```bash
source scripts/env.sh
python -m pytest -q tests/test_quiz_transitions.py
RUN_INTEGRATION=1 python -m pytest -q tests/test_integration.py::test_quiz_structured_transitions_persist_across_pools_and_isolate_users
```

Полный протокол после исправления — [quiz-fix-checks.json](evaluation/quiz-fix-checks.json):
1154 теста прошли, включая 25 проверок PostgreSQL; все 28 критериев приёмки
сохраняются. Модель, Telegram и погодный HTTP в проверках подменены.
Исправление сделано после версии `lab2`; исходный тег сохраняет прежнее состояние.
После обновления перезапустите бот и отправьте `/quiz`, чтобы очистить старую
тренировку с ошибочно засчитанной темой.
