# Ежедневная сводка ЛР3

Согласие по умолчанию выключено. `/briefing_on` требует подтверждённого `/city`,
пользовательской IANA-зоны и адреса личного update. Сводка на локальную дату
планируется к 08:00, допускается до 09:00 включительно. После простоя прошлые дни
не воспроизводятся. Согласие после сегодняшних 08:00 начинает действие завтра.

`BriefingRepository` хранит курсор планирования с версией профиля. Уникальность
`(user_id, local_date)` в outbox защищает от повторного и конкурентного планирования.
Изменение профиля отзывает несохранённый результат. Согласие и версия проверяются
при захвате подготовки, резервировании каждого API, сохранении текста, захвате
отправки и непосредственно перед Telegram. Уже начатый HTTP отозвать нельзя.

Сервис вызывает явные методы ScheduleAgent, LifestyleAgent и KnowledgeAgent через
их MCP-политику. Router для системного запуска не используется. Из БД отдельно
читаются только напоминания владельца в пределах его локальной даты; границы
переводятся в UTC через IANA, без прибавления 24 часов в UTC. В модель эти данные
не передаются. Погода использует только подтверждённую точку, без геокодирования.

Максимум на подготовку — 3 MCP-чтения и 1 LLM; счётчики коммитятся **до** API.
Источники читаются параллельно с пределом 55 секунд на раздел, LLM — 45 секунд,
вся подготовка — 100 секунд. Две захваченные сводки готовятся параллельно,
чтобы второе задание не тратило 150-секундный lease на ожидание первого. Временные пределы не означают обязательного ожидания:
успешный быстрый источник возвращается сразу. Недоступный раздел помечается явно,
остальные сохраняются. Пустое расписание отличается от даты вне покрытия и ошибки.
В сообщении показаны дата, время подготовки и зона; занятия имеют зону расписания.

Фокус выбирается детерминированно по порядковому номеру дня из отсортированных
ID трёх публичных материалов. Поиск ограничен выбранным документом. Кэш
`(catalog_version, topic)` общий, содержит только публичный учебный текст и источник.
Один конкурентный создатель может вызвать модель. Другой или прерванный создатель
использует проверенную выдержку без повторной генерации. Некорректный ответ,
неверная цитата и отказ модели тоже дают выдержку. В кэше нет владельца, истории,
городов и напоминаний. Изменение корпуса меняет ключ кэша.

После потери lease подготовка с потраченным бюджетом завершается ошибкой, не
восстанавливается новым LLM-вызовом. Непотраченная подготовка может быть захвачена
снова. Готовый текст заморожен в outbox: общая доставка повторяет его максимум
три раза, с тем же риском дубля при потере ACK, что и напоминания. Сообщение одно,
проверяется предел 4096 UTF-16; обычный текст отправляется без Telegram parse mode.

`data/schedule-demo.json` — вымышленное расписание 2–15 ноября 2026 года, сдвиг
исходной учебной фикстуры на три недели. Для демонстрации:
`SCHEDULE_FILE=data/schedule-demo.json`. Исходный `data/schedule.json` и фиксированные
часы эксперимента не меняются. Оба публичных файла входят в Docker/cloud-архив;
произвольные личные файлы автоматически не передаются.

Проверки: `tests/test_briefing.py` и `test_daily_briefing_*` в
`tests/test_integration.py`: реальные PostgreSQL, fake clock, fake LLM/Telegram/HTTP.
Реальный суточный запуск в личный Telegram этими тестами не подтверждается.
