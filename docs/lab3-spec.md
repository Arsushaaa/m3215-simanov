# ЛР3: спецификация выбранного решения

Статус на 1 ноября 2026 года: подключены runtime этапа 2 — Router/Supervisor,
политика MCP, `/trace` — и этапа 3: KnowledgeAgent, проверенный каталог и поиск.
Этап 4 добавляет профиль города/уведомлений и исходящую очередь; worker остаётся
следующим этапом. [Настройки и очередь](lab3-notification-settings.md).
[Агенты](lab3-orchestration.md), [материалы и проверки](lab3-materials.md).
Эта спецификация включает целевое поведение следующих этапов и не заменяет приёмку.

Источник требований — [методичка](labs-guide.md#lab3), точный снимок указан в
[lab3-source.json](evaluation/lab3-source.json). Порядок работ —
[lab3-plan.md](lab3-plan.md), правила доверия — [constitution.md](../constitution.md).
База совместимости — неизменяемый `lab2-final-v4` и её исторические протоколы.

## 1. Границы компонентов

Один Python-процесс содержит Supervisor, Router, специалистов и фоновые сервисы.
Сохраняются PostgreSQL, stdio MCP и единственная HTTP-граница модели `app/llm.py`.
Внутренние DTO не объявляются реализацией A2A. Отдельный A2A-сервер остаётся
расширением; отчёт должен описать способ будущего вынесения специалиста.

Router предлагает ровно одну цель; он не получает инструменты и не исполняет задачу.
Supervisor проверяет DTO, привязывает доверенный контекст, вызывает одного
исполнителя, проверяет результат и регистрирует фактически выполненные операции.
Имена Python-классов, поля произвольного JSON и `confidence` не определяют права.

### Маршруты и совместимость

| target | Назначение |
|---|---|
| `schedule` | Занятия и подготовка/правка напоминания |
| `knowledge` | Ответ именно по локальным учебным источникам |
| `lifestyle` | Текущая погода и обоснованные ею рекомендации |
| `legacy_study` | Прежний свободный учебный диалог без MCP |
| `clarify` | Недостаточно данных для выбора одного исполнителя |

`legacy_study` — адаптер существующего режима, не четвёртый специалист.
Он не вызывает старый AgentService со всеми инструментами: используется ответ
без инструментов. Неизвестный маршрут не превращается в этот адаптер.
Перевод и `/quiz` сохраняют собственные правила и одиночный LLM-вызов без Router.
Свободный текст не маршрутизируется по регулярным выражениям.

Перед первым LLM, включая Router, переиспользуется захват запроса/снимка
pending_card в PostgreSQL. Старую кнопку нельзя подтвердить, пока смысл нового
сообщения ещё выясняется. Подготовка, правка, отмена, ошибка и восстановление
действия сохраняют проверки ЛР2. Точный относительный перенос относится к
единственной карточке; свободный ответ не является квитанцией записи.

Успешный несвязанный вопрос сохраняет карточку. Неопределённый исход при активной
карточке обрабатывается безопасным отзывом. История сохраняется атомарно с
проверкой ревизии; `/stop`, `/reset` и смена режима отменяют задачи владельца.
Они не останавливают глобальный worker и не удаляют committed-напоминания.

## 2. Политика MCP

Проверяется пересечение обнаруженного каталога и закрытого списка роли перед
каждым вызовом. Аналогично проверяется доступ к ресурсу и передача его содержимого
в контекст. Новая возможность сервера по умолчанию запрещена.

| Компонент | Инструменты | Ресурсы |
|---|---|---|
| Router, `legacy_study` | нет | нет |
| Schedule | `get_schedule`, `add_reminder` | `schedule://current-week` |
| Knowledge | `search_materials` | `materials://catalog` |
| Lifestyle | `get_weather` | нет |
| BriefingService | чтение через трёх специалистов | только через владельца ресурса |

Настоящий `add_reminder` доступен только в пути callback владельца после
проверки исходного запроса, снимка действия, epoch, срока, параметров и capability.
Модели виден адаптер подготовки `prepare_reminder`, не право записи. Существующая
проверка capability на MCP-сервере сохраняется. Система не исполняет часть списка
действий: при нескольких задачах пользователь выбирает одну.

## 3. Контракты данных

Канонические типы этого этапа — [contracts.py](../app/routing/contracts.py).
Новые модели запрещают лишние поля, проверяют строгие типы, конечные числа,
повторно валидируют экземпляры. Схема не доказывает происхождение или полномочия:
на принимающей стороне дополнительно сверяются контекст, права и фактические вызовы.

### RouteDecision — единственный DTO, предлагаемый Router-моделью

Поля: `target`, `reason`, `confidence`. Цели приведены выше. `reason` — фиксированный
код (`schedule_request`, `materials_request`, `weather_request`, `general_study`,
`ambiguous`), соответствующий цели. Произвольное объяснение не сохраняется в трассе.
`confidence` — конечное число 0..1, bool и строки запрещены. В первой версии
это метаданные эксперимента без порога, который мог бы подменить проверку прав.
Невалидный или неизвестный target даёт безопасное уточнение без специалиста,
без повторного LLM и без исполнения инструментов. Raw JSON пользователю не показывается.

### AgentRequest — конструируется приложением

Поля: UUID `request_id`/`trace_id`, положительный `actor_id` из хранилища,
исходный `text` до 16000 символов, `intent=user_query|daily_briefing`,
aware `occurred_at`, IANA `timezone` либо null, пока настройка не выбрана.
Пробельная строка запрещена, исходный текст не обрезается ради сохранения цитат.

Идентификаторы, intent, часы и зона берутся из доверенных источников.
`model_context()` явно исключает ID и адрес доставки; сериализация всего
AgentRequest в LLM запрещена. Минимальная история и снимок карточки передаются
отдельно по правилам владельца, не из полей решения Router.

### AgentResult — собирается после выполнения

Поля: совпадающие `request_id`/`trace_id`, `status`, `message` до 16000 символов,
опциональный confidence, типизированные `facts`, фактически вызванные
`used_tools`/`used_resources`, фиксированный `error_code`, `pending_action_id`.

Статусы: `success`, `needs_clarification`, `needs_confirmation`, `not_found`,
`failed`, `cancelled`. Ссылка на pending action допустима только для
`needs_confirmation`; наличие такого ID проверяется по БД владельца.
Успех не переносит ошибку, failed требует код. Каждый результат специалиста
допускает суммарно не более одного MCP-вызова. Эти поля не принимает на веру модель.

Варианты facts различаются `kind`: пустые, день/неделя расписания, погода,
результаты поиска. Для MCP переиспользуются прежние проверенные DTO.
Погодная неоднозначность означает уточнение, outside_coverage — отсутствие
данных, а известный пустой день остаётся успехом. Статус и код ошибки сверяются
с результатом источника. Неполный или ложный результат не сохраняется как успех.

Поиск возвращает до пяти фрагментов по 1200 символов с ID документа, названием,
хешем версии и конечной оценкой 0..1. Пустая выдача не становится успешным
ответом по материалам. Пути и произвольные URL не являются идентификаторами.
Каталог содержит публичные метаданные и версии, не секреты или локальные пути.

### TraceSpan — формируется наблюдающим кодом

Связывает UUID трассы, этапа, родителя и запроса; содержит компонент, операцию,
статус, aware начало/конец, длительность, маршрут, имя инструмента/ресурса,
модель, token usage, код ошибки, ID документов и признак кэша. Произвольного
словаря attributes, actor_id, личного текста и промптов в нём нет.
Данные usage при отсутствии метаданных остаются null, а не придуманным нулём.
Начатые этапы имеют null конец/длительность; завершённые — оба значения.
Этап не может быть своим родителем; конец не предшествует началу.
При записи дополнительно сверяются принадлежность родителя и владелец трассы.

Трассы хранятся в PostgreSQL с отдельной служебной связью владельца.
`/trace last` выбирает последнюю операцию до обработки самой команды просмотра,
`/trace <id>` читает только свою. Ошибка сохранения не подменяет новую трассу
старой. Тексты ответа, вопроса и исходящего уведомления не копируются в spans.

## 4. Бюджеты и управление выполнением

Первые шесть пользовательских ограничений подключены на этапе 2.
Пределы доставки и сводки относятся к будущим этапам. Старый AgentService
остаётся совместимым для исторических тестов/протоколов; новый запуск использует Supervisor.

| Сценарий | Максимум LLM | Максимум прикладных MCP |
|---|---:|---:|
| Router просит уточнение | 1 | 0 |
| Свободный `/study` через `legacy_study` | 2 | 0 |
| Погода, материалы, расписание | 3: Router + 2 специалиста | 1 |
| Подготовка, правка, уточнение напоминания | 2 | 0 |
| `/translate`, `/quiz` | 1 | 0 |
| Callback подтверждения/отмены | 0 | не более 1 |
| Доставка уже готового напоминания | 0 | 0 |
| Подготовка одной сводки | не более 1 на учебный фокус | 3 чтения |

Общий бюджет запроса и локальный бюджет специалиста учитываются отдельно.
Прежняя таблица аудита с CHECK LLM<=2 продолжает описывать шаг агента; Router
и полная стоимость отражаются новой трассой. Применённые SQL не переписываются.

Решение Router ограничить 30 секундами, специалиста — прежними 135, Supervisor —
165 суммарно. Финал чтения отключает инструменты. Автоматических LLM/MCP-повторов,
перегенераций и продолжений нет. Действуют границы очередей и частоты ЛР2.
Новые настройки вводятся синхронно в Settings, примерах, Compose и скриптах.

Каталог материалов прогревается отдельной операцией Knowledge при запуске,
проверяется и ограничивается по объёму. Discovery не передаёт содержимое ресурса.
Использование кэша явно отмечается, а не выдаётся за новый MCP-вызов.
При отказе каталога Knowledge сообщает недоступность; другие режимы продолжают работать.
В runtime этапа 3 это ровно одно `resources/read materials://catalog` при инициализации,
отдельно от пользовательского бюджета. Каталог сверяется с реестром из Git и хранится
до перезапуска. Поиск на сообщение — максимум один MCP; пустая выдача не запускает
второй LLM. Показ кэшированного каталога не выдаётся за новый resource read.

Контракт `search_materials`: query 1–200 символов, document_id из реестра либо null,
limit 1–5 (по умолчанию 3). Пути, URL, owner и SQL не являются аргументами.
Результат повторяет параметры и содержит версию каталога, до пяти фрагментов
по 1200 символов, ID, заголовки, версии и конечные score 0..1. Клиент связывает
ответ с параметрами, Knowledge — с каталогом, Supervisor — с наблюдённым вызовом.
CatalogFacts дополняет AgentFacts для показа проверенного каталога.
Ссылки итогового ответа проверяются по найденным ID; цитата должна быть дословным
фрагментом не короче 20 символов. При невалидном итоге показываются ограниченные
выдержки из результата без повторной LLM. Это проверка происхождения цитат,
а не автоматическое доказательство истинности каждого утверждения модели.

## 5. Город и согласие

`/city` геокодирует ввод и показывает нормализованные название, страну, регион.
Координаты и зона места сохраняются только по кнопке владельца; варианты
не выбираются по населению. При неоднозначности выдаются варианты. Город профиля
не подменяет явно названный пользователем город обычного запроса.

`/briefing_on` требует сохранённой зоны и подтверждённого города; ответ показывает
следующие 08:00. Подписка выключена по умолчанию; включение не создаёт рассылку
за время до согласия. `/briefing_off` отменяет будущие/ещё не начатые отправки
сводки. Уже начатый сетевой вызов нельзя объявлять гарантированно отозванным.
`/notifications` показывает настройки без внутренних ID.

`destination_chat_id` хранится отдельно от actor_id и поступает из update личного
чата, а не из текста, модели, MCP или материала. После обновления legacy-пользователь
регистрирует адрес новым доверенным update; адрес не вычисляется из actor_id.
Меню города имеет владельца, случайный токен, срок 5 минут и версию настроек.
Изменение города не удаляет сохранённые напоминания; `/stop` и сброс убирают меню.

Для фоновой погоды нужна подтверждённая точка. Планируется read-only расширение
`get_weather`: отдельная point-ветка с публичными координатами/зоной, без actor_id,
адреса и предоставленной вызывающим подписи города. Обычный LLM видит и проходит
только прежний city-контракт; point-вызов формируется кодом из профиля сводки.
MCP возвращает данные точки, приложение сверяет её с профилем и добавляет подпись
из подтверждённой записи. Так не требуется угадывать место повторным геокодированием
и не появляется способ читать чужой профиль по переданному модели ID.
На этапе 4 реализованы WeatherToolArguments (city либо point) и WeatherToolResult.
Point содержит только latitude, longitude, timezone; ответ повторяет point без подписи
города. MCP-клиент сверяет точку, обычный AgentService получает узкую city-схему,
а ScopedMCP разрешает point только по host-флагу allow_point для Lifestyle.
Поддерживается прежняя полная city-схема сервера; её валидатор point не допускает.

`008_notifications.sql` создаёт профиль, постоянное меню города и outbox.
Настройки и меню меняются с блокировкой user → profile → menu/event.
Сброс/смена режима удаляют меню в транзакции диалога, `/stop` закрывает его через
сервис. Изменение зоны/города/согласия увеличивает profile.version и отменяет
pending/preparing/ready/retry_wait сводки, очищая lease. sending не объявляется
отозванным. Подтверждённый город и сохранённые напоминания при сбросе сохраняются.
Задание напоминания вставляется в транзакции MCP-записи, если адрес уже получен
из update. Legacy без адреса не рассылает ничего; новый update прикрепляет лишь
ещё актуальные напоминания. Службы подготовки/доставки пока не запускаются.

## 6. Исходящие задания и worker

Отдельные события имеют UUID, владельца, тип, адрес из профиля, дедлайн,
подготовленный текст, состояние, lease, счётчик попыток и next_attempt_at.
Уникальность задаётся отдельно по reminder_id и по (владелец, локальная дата сводки).
Повторные/конкурентные подготовки возвращают то же задание. Одна подготовка
не равна гарантии одной внешней доставки.

Состояния: `pending`, `preparing`, `ready`, `sending`, `retry_wait`,
`sent`, `failed`, `missed`, `cancelled`. До HTTP фиксируется попытка, после
подтверждённого успеха — sent. Временная ошибка допускает максимум три попытки
всего, базовые интервалы 30 и 120 секунд с учётом Retry-After и дедлайна.
Постоянная ошибка прекращает обработку. Отправка после дедлайна запрещена.
Неопределённый сетевой исход может привести к дублю при восстановлении;
payload для повтора не генерируется заново.

Предлагаемые параметры: опрос раз в 5 секунд, до 2 исполнителей, партия до 10
заданий, подготовка до 90 секунд, Telegram HTTP до 20 секунд. Lease подготовки
150 секунд, доставки 60; захват имеет версию и проверяется перед отправкой/фиксацией.
Во время внешнего вызова соединение БД не удерживается. На старте подбираются
незавершённые записи с истёкшим lease. На shutdown worker завершается до закрытия
Telegram и БД. Не создаётся отдельный вечный asyncio-таймер на каждое напоминание.

Готовые напоминания доставляются отдельно. При опоздании до 15 минут включительно
добавляется пометка, далее — missed. Будущие события не отправляются заранее.

Сводка привязана к 08:00 пользовательской зоны и одной локальной дате.
После простоя допускается только текущая дата с опозданием до 60 минут
включительно; прошлые дни не догоняются пачкой. Данные дня вычисляются с IANA/DST,
а не прибавлением 24 часов к UTC. Неоднозначный/несуществующий момент обрабатывается
явным безопасным отказом с кодом; произвольный час не подставляется.

Сводка собирает занятия, напоминания дня, погоду точки и короткий учебный фокус
со ссылкой. Отказ раздела оставляет остальные и причину пропуска. Включаются
время подготовки и зона. Согласие/версия профиля проверяются перед началом
отправки; старая подготовка после изменения настроек не даёт новой доставки.
До первого LLM/MCP резервируется сохраняемый слот бюджета события. Прерванная
попытка считается начатой; повтор доставки не запускает новую генерацию.

## 7. Проверка и сдача

[Матрица](evaluation/lab3-acceptance-cases.json) содержит будущие сценарии со статусом
planned. Она не является отчётом об их прохождении. На этапе 1 проверяются
снимок источника, DTO, приватность их полей и согласованность документации.

Обязательный [набор 15](evaluation/lab3-routing.json) не меняется. Реальный
эксперимент получает замороженные модель, настройки, время и источники до API;
измеряется минимум 12 правильных целей, ошибки не исключаются из 15.
Шесть атак проверяются по выполненным действиям, не только по тексту отказа.
Для одного сквозного набора плановый верхний предел 39 LLM включает Router.
Это расчёт, не расход и не разрешение запуска без отдельного протокола/квоты.
