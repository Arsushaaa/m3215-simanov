# Лабораторная № 2: план для обсуждения

Статус: черновик до реализации. MCP-функции ещё не добавлены. План основан на
[методичке](labs-guide.md#lab2), а не на предположениях о задании.

## Что меняется для пользователя

Лабби станет агентом: сможет выбирать разрешённое действие и получать реальные
данные через собственный MCP-сервер. Примеры:

- «Какая сейчас погода в Казани?» → данные погодного сервиса и ответ по ним.
- «Какие занятия завтра?» → чтение подготовленного файла расписания.
- «Напомни завтра в 18:30 отправить отчёт» → уточнение часового пояса при
  необходимости, показ точных параметров, подтверждение и запись в PostgreSQL.

В этой работе напоминание **только сохраняется**. Отправлять уведомление в
назначенное время требуется в лабораторной № 3 (методичка, строки 1110–1111).

## Обязательный результат по методичке

| Часть | Что требуется |
|---|---|
| Собственный MCP-сервер | Инструменты `get_weather(city)`, `get_schedule(date)`, `add_reminder(text, remind_at)`; ресурс только для чтения `schedule://current-week` |
| Контракты | `inputSchema`, `outputSchema`, результат в `structuredContent`; обнаружение возможностей через MCP, без копирования схем в Telegram-обработчики |
| Расписание | Обезличенный файл минимум на две недели в репозитории; путь задаёт конфигурация, не модель |
| Выбор действия | Нативный tool calling; если он недоступен — строгий структурированный вывод с программной проверкой; разбор команд из свободного текста запрещён |
| Ограничение | Не более двух MCP-вызовов на одно сообщение; остановка при превышении, запись аудита |
| Новые команды | `/tools`, `/timezone <IANA-зона>`, `/why`; обновлённая справка `/start` |
| Напоминания | Время в будущем, явный часовой пояс; владелец только из доверенного Telegram update; подтверждение не дольше пяти минут |
| Хранение | Часовой пояс, напоминания, подготовленные действия/подтверждения и аудит — PostgreSQL, с изоляцией пользователей |
| Повторы | Повтор update, повтор MCP-запроса и конкурентное двойное подтверждение не создают дубликатов |
| Документы | До реализации — актуальные `AGENTS.md`, `spec.md`, `plan.md`; после — инструкция, результаты проверок и тег `lab2` |

Полные контракты и правила приведены в методичке: сервер — строки 1032–1120,
бот — 1122–1278, документы — 1280–1316, приёмка — 1438–1460.

## Предлагаемые технические решения

Эти решения ещё можно изменить при обсуждении:

1. **Локальный MCP через `stdio`.** Программа бота запускает сервер отдельным
   дочерним процессом. Публичный порт и новая облачная машина для этого не нужны.
   Такой транспорт рекомендован самой методичкой. При остановке бота корректно
   завершаются MCP-процесс и его соединения.
2. **Официальный Python MCP SDK.** Перед реализацией выбрать и закрепить совместимую
   версию. Не подставлять примеры старой версии SDK без проверки документации.
3. **Open-Meteo для погоды и геокодирования.** При нескольких подходящих городах
   показать различимые варианты и попросить уточнение; не выбирать первый.
4. **Учебное JSON-расписание.** Использовать названия предметов, время и аудиторию,
   без ФИО и других персональных данных. Для демонстрации достаточно фикстуры на
   две недели; подключение университетского аккаунта не требуется.
5. **Подтверждение кнопками.** «Подтвердить» / «Отменить» относятся к одному
   подготовленному действию и владельцу. Повторное нажатие возвращает прежний
   результат. Изменение текста или времени требует нового подтверждения.
6. **Сохранить текущие режимы и `/stop`.** Предварительное предложение — инструменты
   доступны в учебном режиме; перевод и тренировка сохраняют своё поведение.
   Окончательный выбор режима фиксируется в `spec.md` до реализации.

### Ограничение обращений к модели: решение для обсуждения

Сейчас `AGENTS.md` разрешает не более одного LLM-запроса на сообщение. Методичка
требует передать результат чтения модели и сформировать ответ по этому результату
(строки 1257–1262). Обычный сценарий с инструментом поэтому выглядит так:

```text
сообщение → модель выбирает действие → приложение проверяет аргументы
          → MCP выполняет чтение → модель составляет итоговый ответ → Telegram
```

Это два обращения к модели. Предлагаемый консервативный вариант для первой версии:
обычный вопрос — один LLM-запрос; вопрос с инструментом — максимум один MCP-вызов
и два LLM-запроса, второй только для итогового ответа и без новых инструментов.
Один MCP-вызов укладывается в требуемое ограничение «не более двух».

Бесконечное продолжение текста не возвращается: число шагов и общий тайм-аут
ограничены кодом, `/stop` отменяет обработку. Увеличение числа LLM-запросов и
соответствующее изменение правила `AGENTS.md` нужно обсудить до реализации.
Оно увеличит расход общей бесплатной квоты OpenRouter. На этапе реализации также
нужно проверить поддержку tool calling выбранным бесплатным endpoint; платные
запасные модели не добавляются.

## Этапы выполнения

| Этап | Результат | Чем проверяем |
|---|---|---|
| 1. Зафиксировать базу | Работоспособная ЛР1 сохранена в Git; согласованы решения выше; подготовлены `spec.md`, `plan.md` и обновлены правила архитектуры | Текущие проверки проходят, сценарии имеют наблюдаемые результаты |
| 2. Данные и контракты | JSON-расписание; строгие модели аргументов/результатов; миграции часового пояса, подтверждений, напоминаний и аудита | Неверные даты, лишние поля, пустые строки, прошлое время и неизвестные зоны отклоняются |
| 3. MCP-сервер | Три инструмента и ресурс недели, конечные HTTP-тайм-ауты, безопасные ошибки | Успехи и отказы каждого инструмента; ресурс на границе месяца/года; независимый MCP-клиент |
| 4. MCP-клиент и агент | Discovery, проверка решений модели, ограниченное выполнение, корректный ответ при отказе MCP | Обычный ответ, уточнение, разрешённый/неизвестный инструмент, тайм-аут, неправильный результат, предел шагов |
| 5. Подтверждение и команды | `/tools`, `/timezone`, `/why`, кнопки подтверждения, отмена и истечение срока | Нельзя подтвердить чужое действие; изменение требует нового подтверждения; сбой не выдаётся за успех |
| 6. Повторы и безопасность | Идемпотентная подготовка и запись; доверенный владелец вне аргументов модели; безопасный аудит | Настоящий PostgreSQL: повтор update и одновременное двойное подтверждение создают ровно одну запись; недоверенный MCP-клиент получает отказ |
| 7. Эксперимент и сдача | Таблица результатов 12 базовых запросов, анализ ошибок, инструкция и тег `lab2` | Не менее 10/12 правильных действий и 8/9 корректных аргументов; повтор ошибочных кейсов после одного обоснованного изменения |

Каждый завершённый этап сохраняется отдельным коммитом со связанными тестами и
документацией. ЛР2 до обсуждения плана не реализуется.

## Граничные случаи, которые войдут в проверки

- Город не найден, несколько городов с одним названием, погодный API недоступен
  или вернул неправильную структуру.
- Дата неверна; на дату нет занятий; неделя пересекает месяц или год.
- У пользователя нет часового пояса; IANA-зона неизвестна; локальное время
  не существует или встречается дважды при переходе часов.
- Подтверждение просрочено, отменено, повторено, пришло от другого пользователя
  либо относится к уже изменённому действию.
- MCP не запустился или отключился; обычный диалог при этом остаётся доступен,
  а погода и расписание не выдумываются.
- Модель предложила неизвестный инструмент, лишние поля или чужой идентификатор;
  данные инструмента содержат текст, похожий на инструкцию. Запрещённое действие
  не выполняется, секреты не раскрываются.
- Перезапуск не теряет состояние в PostgreSQL; `/stop` прерывает активный
  агентный запрос без запуска следующей генерации.

Обычные тесты используют подменённые Telegram, LLM и погодный API. Отдельно
проверяются реальный MCP-протокол и конкурентные записи PostgreSQL.
Реальные обращения к модели нужны для эксперимента, а не для каждого прогона тестов.
В базовом наборе зафиксированы дата `2026-10-12T09:00:00+03:00` и зона
`Europe/Moscow`; его нельзя привязывать к текущим часам компьютера.
