## Подготовка

1. В BotFather `/setcommands` выбрать своего бота и вставить полный
   [список](botfather-commands.txt). Inline-кнопки создаются кодом.
2. Указать в локальном `.env` собственные BOT_TOKEN и OPENROUTER_API_KEY,
   `OPENROUTER_MODEL=nvidia/nemotron-3.5-super-vl:free`, `LLM_TOOL_MODE=native`.
   Для учебной демонстрации `SCHEDULE_FILE=data/schedule-demo.json`.
3. Выполнить `source scripts/env.sh`, `bash scripts/docker-local.sh start`,
   `bash scripts/start.sh`. Это foreground: процесс должен продолжать работать.
4. В личном чате `/start`, `/study`, `/timezone Europe/Moscow`, `/city Казань`.
   Выбрать реальный вариант, затем подтвердить. `/notifications` покажет профиль.
   Не показывать ключи или полный `.env` на защите.

## Последовательность показа

- «Какие пары у меня завтра?» — Schedule, реальные данные учебного файла;
  `/trace last` показывает цепочку и один MCP. Если дата вне 2–15 ноября, честное
  отсутствие покрытия не означает сбой; подготовить новый публичный fixture,
  не менять прошлый набор эксперимента.
- «По учебным материалам объясни назначение MCP» — Knowledge, найденные
  фрагменты, ID/версия источника. «Найди в материалах квантовую гравитацию» —
  отсутствие ответа в материалах, без дополнения из памяти.
- «Какая сейчас погода в моём городе?» — Lifestyle, профильный город;
  «Погода в Ростове» требует уточнения при нескольких реальных местах.
- «Не забудь мне напомнить через две минуты проверить отчёт» — карточка.
  До кнопки записи нет. Подтвердить и дождаться отдельного уведомления.
  `/stop` после сохранения не отменяет это напоминание.
- `/briefing_on` включает завтрашнюю сводку в08:00; `/briefing_off` отзывает
  не начатые отправки. Суточный запуск нельзя ускорять изменением системных часов.
  Сборку, окно опоздания, DST и сбои показать отдельными fake-clock тестами.
- `/translate` и «На английский: лабораторная работа»; `/quiz`, «Python»;
  проверить один вопрос, `/reset`, `/settings 0.55`.

Формулировки с LLM расходуют квоту; команды просмотра и кнопки — нет.
Не запускать весь реальный эксперимент повторно на защите ради таблицы:
показать сохранённый протокол, хеши и реальные результаты.

## Воспроизводимые проверки сбоев

```bash
source scripts/env.sh
RUN_INTEGRATION=1 .venv/bin/python -m pytest tests/test_integration.py -k 'reminder_delivery or daily_briefing' -q
.venv/bin/python -m pytest tests/test_lab3_security.py -q
.venv/bin/python -m scripts.lab3_acceptance
```

Проверяются отказыTelegram/429, потеряACK, трипопытки, lease, двеодновременные
доставки, перезапуск БД, частичные источники, отсутствиесогласия и чужойcallback.
ТранспортTelegram и LLM в тестах подменены; тесты не пишут преподавателю/пользователю.

## Вопросы для объяснения

- Router выбирает роль, scope выдаёт права; confidence сам не разрешение.
- Подготовка карточки не запись. Только trusted callback + capability + epoch.
- UNIQUE outbox не даёт exactly-once сети; потерянный ACK может дать дубль.
- Города меньше порога населения не исключаются; неоднозначность не устраняется
  переводом на русский и не решается размером города.
- Приватные данные не передаются учебному фокусу; SQL и трассы изолированы владельцем.
- Внутренний Python DTO не A2A. Сетевое вынесение потребует отдельного transport,
  аутентификации, корреляции, отмены и прежней проверки прав.
