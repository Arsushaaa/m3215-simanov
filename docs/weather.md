# Поиск города и ошибки погодного сервиса

В режиме `/study` инструмент `get_weather` получает текущие наблюдения
Open-Meteo. Сначала выполняется геокодирование, затем — запрос погоды только
для однозначно найденного места. Страна и регион передаются через запятые:
`Казань, Россия, Татарстан`. Минимального населения и выбора крупнейшего города нет.

## Исправление неоднозначности — 19 октября 2026 года

Реальный публичный ответ геокодера на `Казань` сохранён в
[`open_meteo_kazan.json`](../tests/fixtures/open_meteo_kazan.json). В нём есть
Казань в Татарстане и три населённых пункта в Кировской области с разными
GeoNames ID и координатами, но одинаковыми доступными подписями. Прежде эти
повторы превращали весь поиск в `INVALID_ARGUMENTS`; клиент показывал сообщение
«Аргументы инструмента не соответствуют допустимому формату».

Теперь для выбора показываются уникальные подписи, а исходные места сохраняются
раздельно. `Казань` даёт уточнение с вариантами в Татарстане и Кировской области.
`Казань, Татарстан` однозначно определяет координаты и разрешает запрос погоды.
`Казань, Кировская область` по-прежнему обозначает три места: бот выдаёт
`AMBIGUOUS_PLACE` с понятным сообщением о недостаточной точности геокодера.
Превращать этот вариант в одну локацию или брать первый ID запрещено.

Клиент показывает фиксированное безопасное сообщение для нового кода;
произвольный текст ошибки сервера не передаётся пользователю. Общий лимит
остаётся прежним: один прикладной MCP-вызов и не более двух LLM-запросов для
чтения. Автоматических повторов HTTP, MCP или LLM нет.

## Внешний отказ и диагностика

Сообщение «Внешний сервис сейчас недоступен» означает HTTP-отказ или ошибку
соединения. Скриншот не позволяет определить, отказал геокодер или погодный
endpoint. Проверка настоящим `WeatherService` 19 октября 2026 года получила
успешные ответы обоих endpoint для `Ростов-на-Дону`. Прежний сетевой отказ не
воспроизведён; эта проверка не гарантирует постоянную доступность Open-Meteo.

Для следующего отказа в stderr добавлена ограниченная диагностика, например:

```text
WARNING weather phase=current code=UPSTREAM_ERROR http_status=503 error_type=_FetchError
```

Значение `phase=geocoding` относится к поиску города, `phase=current` — к
получению наблюдения. При сетевой ошибке без HTTP-ответа `http_status=None`.
Логи не содержат названия города, URL, ответа HTTP, текста исключения или
traceback. stdout дочернего процесса остаётся только транспортом MCP.

## Проверки

Регрессии используют захваченный публичный ответ и подменённый HTTP: повторяющиеся
подписи, уточнение региона, маленькие населённые пункты, повреждённые данные,
HTTP 403/429/503, сетевые ошибки, общий тайм-аут и отсутствие повторов.
Отдельная проверка прогоняет безопасную диагностику через настоящий фильтр
логирования stdio-сервера. Новый код проверен Pydantic, JSON Schema и клиентом MCP.

Полный протокол проверок, включая PostgreSQL:
[`weather-fix-checks.json`](evaluation/weather-fix-checks.json).
Прошли 1179 тестов без пропусков и все 28 критериев ЛР2; зависимости,
Ruff и форматирование проверены. Миграции и исходный набор эксперимента сохранены.
Реальная квота OpenRouter при исправлении не использовалась.

Описание полей первичного источника:
[Open-Meteo Geocoding API](https://open-meteo.com/en/docs/geocoding-api).
