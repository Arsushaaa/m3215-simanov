# Проверки устойчивости — 28 октября 2026 года

Проверка продолжает `lab2-final-v2`; опубликованные теги не перемещаются.
Открытое пользователем окно Telegram Desktop и затем Chrome не появилось
в доступных инструменту UI окнах/браузерах (`apps=[]`, `browsers=[]`).
Скриншот подтверждает открытый клиент, но не даёт управления им.
Поэтому автоматический прогон ниже проверяет приложение, а не настоящий UI.
Скриншот с открытым `.env` в репозиторий не сохраняется.

## Исправление переполнения очередей

На подменённых Telegram/LLM воспроизведены два пробела прежнего тега:
30 сообщений при заблокированной генерации оставляли 30 задач; 30 `/tools`
создавали отдельную очередь из 30 команд, ожидающих пользовательскую блокировку.
Реальные API в этой проверке не использовались.

Новый `app/request_limits.py` ограничивает процесс:

- Генерации: максимум две принятых на пользователя, 16 суммарно, четыре
  выполняемых одновременно; восемь принятых за 60 секунд на пользователя.
- Обычные команды: отдельная очередь до двух на пользователя и 16 суммарно,
  без расхода лимита генераций.
- Управляющие команды/callback объединяются по владельцу и фиксированной группе,
  до 64 одновременно; для `/stop` владельцев с генерациями есть резерв 16.
- Каждый `/stop` отменяет текущие задачи; повторные сообщения не строят очередь
  запросов к БД. Отмена напоминания не блокируется занятым подтверждением.
- Уведомления о перегрузке объединяются. Ошибка или отмена освобождает очередь,
  но не возвращает принятый запрос в минутный лимит.

Регрессии: `test_burst_cannot_build_an_unbounded_generation_or_rejection_reply_queue`,
`test_read_command_flood_is_bounded_before_user_lock_and_stop_clears_it`,
`test_stop_flood_coalesces_before_database_and_blocks_new_generation`,
проверки callback и `tests/test_request_limits.py`.

Это ограничение всплесков/ожидания в одном процессе. Оно не гарантирует
сохранность общей суточной квоты публичного бота от всех пользователей.
Перезапуск очищает временные счётчики; Telegram identity и права записи
по-прежнему проверяются отдельно.

## Реальный ограниченный прогон приложения

`scripts/lab2_adversarial_live.py` использует production aiogram Dispatcher,
обработчики, диалог, агента, настоящий OpenRouter и MCP stdio. PostgreSQL
поднимается в отдельном контейнере/volume, которые удаляются по завершении;
пользовательская история и напоминания не затрагиваются. Подменён только
Telegram transport: реальные сообщения и кнопки в Telegram не отправляются.

До API фиксируются запросы, критерии, исходники, каталог и часы в манифесте,
который требуется закоммитить. Десять потоков требуют до 15 LLM; дополнительно
стоит жёсткая граница 24 и сохраняемый остаток квоты 15. Слот сохраняется
до dispatch; уже начатый прогон не повторяется, ошибки остаются из десяти.
Ожидания модели не передаются. Запись проверяется по SQL, а не обещанию модели.

Потоки: недопустимые настройки, отрицание напоминания, цитата, несколько действий,
английское имя города с реальным чтением погоды, расписание на покрытую дату,
попытка текстового подтверждения и чужая кнопка, перенос карточки/старая кнопка,
перевод цитаты с инъекцией, попытка перескочить викторину и запрос подсказки.

Первый [протокол](evaluation/lab2-adversarial-live-20261028/manifest.json) и
[результат](evaluation/lab2-adversarial-live-20261028/results.json): **8/10**,
15 LLM, три прикладных MCP, стоимость API 0. Все десять потоков сохранены.

Два неуспеха:

1. Измеритель ошибочно ожидал единственную Казань в России. Open-Meteo вернул
   Татарстан и Кировскую область; бот корректно попросил уточнение. Полезная
   защита от выбора первого/самого крупного города сохраняется. В новом
   протоколе будет отдельное уточнение региона; прежний результат не меняется.
2. При переносе на два часа модель вычислила правильные 21:00 и задачу,
   но сослалась на message_index=2 для текущей реплики с индексом 0.
   Проверка источника отклонила предложение, старая карточка отозвана.
   Исправление контекста будет явно индексировать текущую реплику; проверку
   дословных пользовательских цитат ослаблять нельзя.

Первый [полный офлайн-прогон](evaluation/lab2-adversarial-offline-20261028.json):
1423 passed, два failed, пропусков нет. Оба неуспеха — старый измеритель ЛР1,
который отправлял искусственные сообщения быстрее нового лимита 8/минуту.
Текущий измеритель должен соблюдать паузу, а не отключать защиту; исторические
входы, результаты и теги ЛР1 не меняются.

Пользователь затем разрешил весь бюджет 50 LLM-вызовов этой проверки.
Новые протоколы учитывают уже начатые 15, не обнуляют общий счётчик и не
повторяют старый checkpoint. Успех ограниченного набора не доказывает
отсутствие всех ошибок и не заменяет проверку UI/доставки.
