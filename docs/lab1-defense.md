# Демонстрация и защита лабораторной № 1

Сценарий относится к сдаваемой версии с тегом `lab1`. Это инструкция для
предстоящего показа, а не утверждение, что весь показ уже проведён в живом чате.
Фактически выполнены 18 API-вызовов: 12 температурных, 2 сравнения инструкций
и 4 сквозных проверки с отдельной PostgreSQL и подменённым Telegram;
также прошли 230 автоматических тестов, включая интеграционные.
Демонстрация двух живых Telegram-аккаунтов и показ всех трёх режимов ниже
выполняются при защите. Основные материалы:
[отчёт](lab1-report.md), [запуск](local-environment.md),
[требования](labs-guide.md#критерии-приёмки),
[репозиторий](https://github.com/Arsushaaa/m3215-simanov).

## 1. Подготовить показ

Потребуются работающий интернет, Docker, Python 3.12 из `.venv`, настроенный
локальный `.env` и два Telegram-аккаунта для демонстрации независимых диалогов.
Не открывайте `.env`, полный вывод окружения или личные переписки при записи
экрана. Для примеров используйте только вымышленные учебные данные.

Из корня проекта в своём терминале:

```bash
source scripts/env.sh
bash scripts/docker-local.sh start
bash scripts/start.sh
```

Оставьте процесс работающим. Если среда завершает фоновые процессы,
`bash scripts/docker-local.sh run` выполняется в отдельном открытом терминале.
В другом терминале:

```bash
source scripts/env.sh
python -m app.healthcheck
```

Healthcheck проверяет готовность приложения и его соединение с PostgreSQL;
положительный результат не подтверждает доступность LLM на каждый будущий
запрос. В логах запуска покажите успешное подключение PostgreSQL, проверку
Telegram и polling. Не запускайте два polling-процесса с одним токеном.

## 2. Показать функции на действительной модели

В первом Telegram-аккаунте последовательно выполните:

1. `/start`: список команд, текущий режим.
2. `/study`, затем «Объясни разницу между списком и кортежем в Python.
   Приведи короткий пример». Покажите осмысленное объяснение, выделения и код.
3. «Какой из них можно изменять?»: продемонстрируйте использование контекста.
4. `/translate`, затем «На английский: Я завершил лабораторную работу».
   При смене режима старая история очищается.
5. `/translate`, затем «Переведи: Добрый вечер!» — бот должен уточнить язык.
6. `/quiz`, затем «Тема: циклы for в Python». Покажите один вопрос, ответьте
   на него и запросите «Подсказка» к следующему. Номер подсказкой не увеличивается.
7. `/settings 0.55`, затем `/settings`: любое значение в диапазоне разрешено.
   `/settings 1.2` отклоняется, прежняя температура сохраняется.

Эти сообщения расходуют внешнюю квоту. Полную тренировку из пяти вопросов
можно показать при достаточной квоте; её порядок и сохранение состояния также
проверяются автоматически. Не представляйте ответы заглушки как ответы модели.

## 3. Два пользователя и перезапуск

Используйте только свои демонстрационные аккаунты; `/reset` удаляет историю
того аккаунта, из которого вызван. Перед сбросом сохраните нужные материалы.

1. В аккаунте А: `/study`, `/settings 0.3`, затем
   «Запомни учебную метку А: янтарь-17». Дождитесь ответа.
2. В аккаунте Б: `/translate`, `/settings 0.7`, затем
   «На английский: Учебная метка Б — кедр-42». Дождитесь ответа.
3. Покажите `/settings` у обоих: разные режимы и температуры.
4. Остановите только Python-процесс клавишами `Ctrl+C` и снова выполните
   `bash scripts/start.sh`. Volume и контейнер БД не удаляются.
5. После healthcheck снова покажите настройки обоих аккаунтов.
6. В А спросите «Какую учебную метку я попросил запомнить?».
   В Б попросите перевести фразу про его метку с учётом предыдущего направления.
   Объясните, что новое приложение получило данные из PostgreSQL.
7. Выполните `/reset` только в А. Покажите, что его режим и температура
   сохранены, а Б продолжает свой диалог. Отсутствие чужих строк и точное
   поведение репозитория дополнительно подтверждаются интеграционным тестом.

Ответ LLM на проверку памяти не является единственным доказательством
изоляции: модель может ошибиться. Покажите автоматическую проверку с двумя
синтетическими `user_id`, параметризованными SQL и новым соединением БД:

```bash
source scripts/env.sh
RUN_INTEGRATION=1 python -m pytest -q tests/test_integration.py
```

Эти тесты сами создают временный контейнер и volume с префиксом `itmo-test-`,
а затем удаляют только свои ресурсы. Учебная PostgreSQL не очищается.

## 4. Воспроизводимо показать ошибку LLM и длинный ответ

Заведомо вызывать сбой внешнего провайдера или расходовать квоту на гигантское
эссе не требуется. Следующие проверки используют контролируемые подмены;
перед показом прямо назовите это тестированием поведения приложения,
а не генерацией действительной модели.

```bash
source scripts/env.sh
python -m pytest -q tests/test_llm.py
python -m pytest -q tests/test_handlers.py -k 'safe_error or long_answer or long_code or truncated_answer'
python -m pytest -q tests/test_dialog.py -k 'model_failure or truncated_text or continuation_preserves_tail'
```

Покажите в коде выбранных тестов:

- искусственный таймаут, сетевую ошибку, HTTP `429` и пустой ответ;
- точное безопасное сообщение пользователю и отсутствие новой пары в истории;
- управляемый текст длиннее 4096 символов, реальные обработчик и форматтер,
  перехваченные вызовы Telegram; длину каждой части, порядок и восстановление
  исходного текста без потерь;
- длинный код с emoji: длина ограничивается в единицах UTF-16, entities
  сохраняются на каждой части;
- результат модели с `finish_reason=length`: полученный текст не отбрасывается,
  сохраняется признак неполноты, отдельное «Продолжи» вызывает ровно один новый
  запрос после восстановления сервиса.

Лимит Telegram и лимит генерации независимы: готовый ответ может разделяться
без новых обращений к модели; продолжение генерации требует нового сообщения.

В дополнительной [проверке режимов](evaluation/lab1-smoke.json) получены четыре
реальных ответа без перегенераций и с API-стоимостью 0. Изоляция настроек
и истории сохранена; после пересоздания пула БД, клиента и dispatcher модель
вспомнила «маяк-47». Проверены `/study`, `/translate`, первый вопрос `/quiz`.
Последний раскрыл правильный вывод кода в примере ожидаемого формата — это
наблюдённое ограничение LLM, хотя номер 1/5 и прогресс БД правильны.
Не представляйте эту проверку как живой показ двух Telegram-аккаунтов
или полный перезапуск ОС.

## 5. Показать ограничения объёма и отмену

В своём демонстрационном аккаунте:

1. `/study`, затем «Напиши эссе на 10000 слов»: сначала уточняется тема.
2. «Про C++ на огромное количество слов»: бот предупреждает об объёме
   до обращения к модели. Объясните локальную проверку без второго LLM-запроса.
3. Отправьте обычный учебный вопрос. Пока формируется ответ, отправьте `/stop`.
   Поведение при быстром готовом ответе зависит от времени доставки команды;
   точную отмену активного и уже ожидающего запросов покажите контролируемым тестом:

```bash
source scripts/env.sh
python -m pytest -q tests/test_handlers.py -k 'stop or reset_interrupts'
python -m pytest -q tests/test_reply_control.py tests/test_output_limits.py
```

`/reset` и смена режима также прерывают активную работу. Автоматической
цепочки продолжений нет. Уже доставленное сообщение `/stop` не удаляет.

## 6. Представить эксперимент и ответить на пограничный вопрос

Откройте раздел эксперимента [в отчёте](lab1-report.md#5-эксперимент-температура-и-улучшение-инструкции):
12 запусков на действительной модели, четыре температуры по три попытки,
сброс истории и одинаковые остальные условия. Откройте также
[подробный анализ](evaluation/lab1-experiment.md) и
[исходные ответы](evaluation/lab1-results.json). Все 14 вызовов успешны;
формат температурного задания выполнен в 11/12. Не скрывайте ошибки:
последний ответ превысил 180 слов, а улучшенная инструкция в отдельной паре
не добилась объяснения присваивания. Покажите оба ответа и назовите заранее
принятые критерии; компактность не равна полной корректности.

Для вопроса «Что если ответ записан, а Telegram не принял сообщение?»:

> Сначала сохраняется успешная пара, затем отправляется ответ. Поэтому в БД
> может остаться ответ, которого пользователь не видел. При Telegram `429`
> есть ограниченный повтор; постоянной очереди доставки пока нет. `is_complete`
> описывает завершённость генерации, не доставку. Для восстановления после
> сбоя нужен outbox с заданиями отправки, но при потере подтверждения Telegram
> всё равно нельзя безусловно обещать отсутствие дублей.

Объясните также приблизительную оценку токенов, вероятность ошибок модели,
зависимость от сети и внешней квоты, хранение ключей и маскирование журналов.

## 8. Как показывать ЛР1 после разработки ЛР2

Тег сохраняет состояние отслеживаемых файлов, но не `.env`, окружение Python
и содержимое PostgreSQL. При необходимости подготовьте дополнительную рабочую
папку версии `lab1` через Git worktree или отдельный clone; основная папка
может оставаться на ЛР2. Пример из основной папки после создания тега:

```bash
git worktree add --detach ../ai_labwork-lab1 lab1
```

В новой папке создайте собственную `.venv`, безопасно настройте отдельный
локальный `.env`, отдельный volume/базу и свободный порт PostgreSQL/healthcheck.
Не подключайте старый код к общей изменённой БД ЛР2. Один Telegram-токен
запускается по очереди из нужной папки; для одновременного показа нужны разные
боты. Не удаляйте пользовательские данные и не выполняйте откат миграций ради
переключения версии. Подробности выбранного запуска согласуются с фактической
структурой окружения на момент защиты.
