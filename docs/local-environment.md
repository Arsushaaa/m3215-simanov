# Подготовленное локальное окружение

Дата подготовки: 14 октября 2026 года. Окружение создано в каталоге проекта
на Linux без замены системного Python и без установки системного Docker.

## Установленные компоненты

- Python 3.12.15 — `.tools/python/`, окружение приложения — `.venv/`.
- Все зависимости из `requirements-dev.txt`, включая `requirements.txt`
  и закреплённые версии из `constraints.txt`.
- uv 0.13.1 — `.tools/bootstrap/bin/uv`.
- Docker 29.9.0 — `.tools/docker/bin/`.
- Docker Compose 5.6.0 — `.tools/docker/cli-plugins/`; используется команда
  `docker compose`, совместимая со скриптами проекта.
- slirp4netns 1.3.6 — сеть Docker без прав администратора.
- PostgreSQL — образ `postgres:16-bookworm`.

`.tools/` и `.venv/` исключены из Git. Данные этого Docker хранятся в
`.tools/docker-data/`, сокет — в `.tools/docker-run/docker.sock`.
Для нового компьютера зависимости устанавливаются заново; переносить эти
каталоги как готовое окружение не следует.

## Работа из терминала

Из корня проекта:

```bash
source scripts/env.sh
bash scripts/docker-local.sh start
```

Первая команда выбирает Python и Docker проекта. Вторая запускает Docker
в фоне без `sudo`. Если терминал или среда исполнения принудительно завершает
фоновые процессы, запустите Docker в отдельном терминале:

```bash
bash scripts/docker-local.sh run
```

Оставьте этот терминал открытым. Проверка и остановка:

```bash
bash scripts/docker-local.sh status
bash scripts/docker-local.sh stop
```

Остановка Docker сохраняет данные БД. Для остановки только БД используйте
штатную команду `bash scripts/start.sh stop` после активации окружения.

## Ключи и настройки

В корне создан `.env` с правами `600`. Пароль PostgreSQL сгенерирован;
реальные токен Telegram и ключ OpenRouter нужно вставить самостоятельно:

```dotenv
BOT_TOKEN=токен_из_BotFather
OPENROUTER_API_KEY=ключ_из_OpenRouter
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
OPENROUTER_MODEL=nvidia/nemotron-3-super-120b-a12b:free
```

Токен Telegram создаётся через [BotFather](https://t.me/BotFather).
Ключ модели создаётся в [OpenRouter Keys](https://openrouter.ai/settings/keys).
Это два разных ключа: первый разрешает программе работать с Telegram,
второй — обращаться к моделям через OpenRouter. `.env` исключён из Git;
секреты не нужно присылать в чат или записывать в `DIALOG.json`.

**OpenRouter-клиент подключён к боту.** Личные текстовые сообщения отправляются
модели с системной инструкцией выбранного режима и историей из PostgreSQL.
HTTP-клиент использует уже установленный `aiohttp`; дополнительный SDK не нужен.
Для запуска приложения ключ OpenRouter обязателен. `--setup-only` позволяет
подготовить БД без обращения к модели.

После добавления токена Telegram и ключа OpenRouter бот запускается так:

```bash
source scripts/env.sh
bash scripts/docker-local.sh start
bash scripts/start.sh
```

В IDE выберите `.venv/bin/python`, запуск модуля `app`, рабочую папку — корень
проекта. Для подготовки БД без запуска бота используйте
`bash scripts/start.sh --setup-only` после добавления токена Telegram.

## Если бот не отвечает в Telegram

Открытие чата в Telegram не запускает программу. Локальный `start.sh`
запускает бот в текущем терминале; после завершения процесса, закрытия его
сессии или остановки компьютера команды не обрабатываются. Запуск из сессии
ассистента также не гарантирует работу после завершения этой сессии.

Чтобы восстановить работу, выполните из корня проекта в своём терминале:

```bash
source scripts/env.sh
bash scripts/docker-local.sh start
bash scripts/start.sh
```

Оставьте терминал с ботом открытым. Если среда завершает фоновые процессы,
вместо `docker-local.sh start` используйте `docker-local.sh run` в отдельном
открытом терминале. Уже работающий Docker повторно запускаться не будет.
Не запускайте второй экземпляр бота с тем же токеном.

В другом терминале проверьте готовность:

```bash
source scripts/env.sh
python -m app.healthcheck
```

После сообщения `Telegram доступен` и запуска polling отправьте `/start`
в Telegram. Если healthcheck проходит, но команды остаются без ответа,
проверьте логи бота на ошибки сети, токена или конфликт второго polling.
Для постоянной работы после выхода из IDE нужен отдельный постоянно
работающий запуск, например предусмотренный в проекте деплой на сервер.

## Где что работает

При разработке Python-бот и PostgreSQL работают на компьютере.
Telegram и OpenRouter доступны через интернет. Модель выполняется у
провайдера, выбранного OpenRouter; её веса на компьютер не скачиваются.

Бот получает сообщения через long polling: программа сама обращается к
Telegram. Поэтому для локальной разработки публичный IP, домен и входящий
HTTP-порт не нужны. Пока программа остановлена, она не обрабатывает сообщения.
Один токен должен использоваться одним активным polling-процессом.

Отдельная ВМ нужна для круглосуточной работы или облачной сдачи по требованиям
преподавателя. В репозитории уже есть деплой в Yandex Cloud. Он запускает бот
и PostgreSQL в Docker на одной ВМ и требует внешний прокси для Telegram.
Параметр `TELEGRAM_PROXY_URL` относится только к Telegram.
В опубликованных требованиях лабораторной № 1 обязательная аренда ВМ не указана.

## Выбор модели

По просьбе пользователя выбран бесплатный вариант:
`nvidia/nemotron-3-super-120b-a12b:free` — NVIDIA Nemotron 3 Super.
На 14 октября 2026 года стоимость входных и выходных токенов равна нулю.
Поддержка `temperature`, `tools`, `response_format` и `structured_outputs`
проверена по [открытому каталогу API](https://openrouter.ai/api/v1/models).
Это подходит требованиям лабораторной № 1 и будущим MCP-инструментам.
Выбранная модель проверена реальными запросами в трёх режимах: объяснение
по программированию, перевод и первый вопрос тренировки. Также проверено
использование истории после переподключения к БД. Сравнительную оценку качества
на учебном наборе ещё предстоит выполнить.

Для бесплатного аккаунта базовый лимит OpenRouter — 50 запросов в сутки и
20 в минуту. Это общая квота `:free` аккаунта, а не отдельная квота каждой
модели или пользователя бота. Стандартный вариант увеличения — один раз
купить кредиты на $10: суточная квота становится 1000 запросов, минутная остаётся
20. Это пополнение, а не подписка; запросы к `:free` остаются без оплаты токенов.
Конкретные лимиты аккаунта можно проверить через `GET /api/v1/key` после
настройки ключа. Переход между бесплатными моделями базовую квоту не увеличивает.
Сравнение пяти вариантов сохранено в [выборе модели](model-comparison.md);
пользователь подтвердил Nemotron 3 Super в бесплатной версии.
При исчерпании лимита бот должен сообщить об этом и сохранить текущую историю;
автоматический переход на платную модель не предусмотрен. API-ключ нужен и
для бесплатной модели. Историю и длину ответа всё равно нужно ограничивать.

Бесплатный endpoint NVIDIA журналирует запросы для безопасности и улучшения
сервиса. Для лабораторной используйте учебные примеры без секретов и
конфиденциальных данных; политика указана на карточке модели.

Имя бота, описания, команды и аватар подготовлены в [профиле BotFather](botfather.md).

## Реализованная функциональность и следующие этапы

- Реализованы миграции, история и настройки в PostgreSQL.
- Подключён асинхронный OpenRouter-клиент; платные модели и повторные запросы
  автоматически не выбираются. При ошибке новая пара не сохраняется.
- Работают `/start`, `/study`, `/translate`, `/quiz`, `/settings`, `/stop` и `/reset`.
- Включены лимиты контекста, разделение пользователей, последовательная
  обработка сообщений одного пользователя и разбиение длинных ответов.
- Следующие этапы: эксперимент из методички и отчёт, затем MCP-инструменты
  лабораторной № 2. Облачный деплой — по требованиям курса или для постоянной работы.

Примеры в личном чате:

```text
/study
Объясни разницу между списком и кортежем в Python.
/translate
На английский: Я закончил лабораторную работу.
/quiz
Тема: циклы for в Python.
/settings 0.7
/settings 0.55
/reset
```

Смена режима очищает только свою историю. `/reset` сохраняет выбранный режим
и температуру. `/start` показывает текущий режим, сохраняя контекст.
`/stop` отменяет активный ответ и все свои ожидающие текстовые запросы.
`/reset` и смена режима тоже сначала отменяют их, поэтому доступны во время генерации.
При просьбе написать эссе без темы бот сначала спрашивает тему без вызова модели;
уточнение сохраняется в истории. Несвязанная старая тема не выбирается самостоятельно.
`/settings` принимает любое число от 0 до 1 включительно, например `0.55`
или `0,125`. Значение хранится как число двойной точности; в ответе отображается
сохранённое значение, без округления до одного знака.
Для `/translate` целевой язык можно указать в первом сообщении; затем он
учитывается через историю диалога.
Для `/quiz` тема, номер вопроса и завершение хранятся в PostgreSQL. Нумерацию
добавляет приложение; после пятого ответа тренировка завершается. Напишите
«Подсказка» или «Дай подсказку», чтобы получить подсказку без перехода к
следующему вопросу. Новая тренировка начинается командой `/quiz`.

Лимиты задаются в `.env`: `HISTORY_MAX_MESSAGES=20` (чётное число не менее 4),
`HISTORY_MAX_TOKENS=6000` (не менее 1024),
`LLM_MAX_OUTPUT_TOKENS=2048`, `LLM_TIMEOUT_SECONDS=60`. Число токенов входа
оценивается по UTF-8 (байты / 3, округление вверх, плюс 4 на сообщение).
Старые пары исключаются целиком. В PostgreSQL архив остаётся до сброса или
смены режима. Слишком большой текущий вопрос отклоняется до API-вызова.

Форматирование Markdown преобразуется в Telegram entities: заголовки, жирный
и курсивный текст, ссылки, строчный код и блоки кода. Цитаты Markdown через `>`
выводятся обычными абзацами с сохранением кода и выделений: Telegram-цитата
больше не разрезается вокруг каждого фрагмента строчного кода на мелкие плашки. Длинный ответ
разбивается на части до 4096 единиц UTF-16 с сохранением выделений; по возможности
разрыв проходит по пробелу или переносу строки. При ограничении частоты Telegram
повторяется отправка той же части, без нового запроса к модели.

Запросы на чрезмерный объём, например «напиши эссе о C++ на 10000 слов», «напиши огромное
эссе о C++» или «напиши эссе по теме C++ на огромное количество слов», проверяются
локально до API-вызова, без отдельного запроса к модели и расхода квоты.
Эссе без темы сначала вызывает уточнение темы. Просьбы «в три раза
длиннее» сравниваются с последним сохранённым ответом. Бот сразу предлагает
написать текст по частям. Это оценка бюджета и явных формулировок,
а не точный токенизатор или универсальный анализ смысла.

Если модель остановится с `finish_reason=length`, бот отправит весь полученный
текст с предупреждением о неполноте. Пара сохраняется атомарно с
`is_complete=false` у ответа. Напишите «Продолжи»: история и состояние неполноты
сохраняются после перезапуска. Продолжение получает конец предыдущего ответа,
даже если целиком он не влезает в контекст. Новый API-вызов запускает пользователь;
скрытых повторов нет. Неполный ответ не продвигает счётчик вопросов `/quiz`.
Превышение размера сообщения Telegram обрабатывается разбиением уже готового
ответа. Эти два ограничения независимы.

Источники реализации: [форматирование и entities Telegram](https://core.telegram.org/bots/api#formatting-options),
[ограничение sendMessage](https://core.telegram.org/bots/api#sendmessage),
[парсер Markdown](https://markdown-it-py.readthedocs.io/en/latest/using.html).
[OpenRouter: формат ответа и finish_reason](https://openrouter.ai/docs/api_reference/overview#completionsresponse-format).

## Проверки

После исправлений 15 октября 2026 года прошли все **220 тестов**, включая проверки на настоящем
PostgreSQL: миграции, восстановление истории и прогресса тренировки,
разделение пользователей, атомарная запись и защита от устаревших ответов.
Проверены отображение Markdown, длинные блоки кода с emoji, порядок частей,
повтор отправки после ограничения Telegram, произвольные температуры и
предварительное отклонение чрезмерного объёма. Миграция диапазона проверена
на заполненной БД со старым ограничением температуры; история сохранилась.
Проверены запросы без указанного числа, увеличение прошлого ответа в три раза,
отправка всего обрезанного текста по частям, восстановление состояния неполноты
из PostgreSQL и продолжение с сохранением конца ответа при обрезке контекста.
Автоматическая цепочка из предыдущей версии отменена: на сообщение вызывается
не более одной генерации. Дополнительно проверены эссе без темы, сохранение
уточнения после перезапуска, отмена активного и ожидающих запросов через `/stop`,
прерывание через `/reset` и возможность отправить новый запрос после остановки.
Дополнительно проверены цитаты с inline-кодом без дробления на плашки,
чрезмерный объём после темы эссе и после уточняющего вопроса, а также отсутствие
ложного отказа для переводимых фраз и размеров входного материала.
Проверки Ruff и `pip check` также прошли.
Образ `labbi:local` успешно собран из Dockerfile с установкой зависимостей
только из wheel-пакетов, включая новый парсер Markdown.

В ходе реализации выполнено пять реальных запросов к выбранной модели:
учебное объяснение, обращение к сохранённой истории после переподключения,
перевод, вопрос тренировки и проверка сохранения его номера. Модель вспомнила
значение `17` из предыдущего сообщения. Проверочные записи удалены из БД.
Это проверка работоспособности, а не оценка всего набора учебных заданий.

На момент завершения реализации бот `@labbi_study_bot` запущен локально
через long polling, PostgreSQL работает на `127.0.0.1:5432`.
Применены миграции `001_dialog.sql`, `002_quiz_progress.sql`, `003_temperature_range.sql`
`004_incomplete_answers.sql` и `005_response_parts.sql`;
последняя сохранена для совместимости, её столбец `parts` текущим кодом не используется;
healthcheck подтвердил готовность polling и успешный `SELECT 1`.
Чтобы попробовать бота, откройте личный чат в Telegram и отправьте `/start`.
Для следующего запуска используйте инструкцию выше, предварительно остановив
работающий экземпляр. Секреты в документацию не копировались.

```bash
source scripts/env.sh
python -m pip check
python -m ruff check .
python -m ruff format --check .
python -m pytest -q
RUN_INTEGRATION=1 python -m pytest -m integration -v
```

Интеграционный тест создаёт собственные контейнер и volume, затем удаляет
только эти тестовые ресурсы. Реальные ключи Telegram и OpenRouter для тестов
не требуются.
